# 둘 · 동네친구, 데이트, 새로운 시작

취향이 가까운 사람을 찾아주는 매칭 웹앱이에요.
추천 상대와 함께 **왜 그 사람을 골랐는지(매칭 로직)**를 화면에서 보여주는 것이 목표예요.

## 주요 기능

- **회원가입·로그인**: Firebase 인증(아이디 + 비밀번호), 만 19세 이상, 프로필 사진, 생활 패턴·원하는 상대 조건을 가입 때 직접 선택
- **회원 탈퇴**: 프로필·사진·보낸 좋아요·마음 표현과 계정을 지움
- **오늘의 추천 3명**: 하루 동안 같은 3명, 다음 날은 최근 14일 안에 본 사람을 뒤로 보내고 새로 골라줌 (하루 3번까지 "한 명 더 보기")
- **조건 완화 제안**: 후보가 없거나 적으면 "최대 거리 15km → 30km · +12명"처럼 실제로 늘어나는 인원을 세어서 버튼으로 제안
- **자동 매칭**: 서로의 추천 상위 3명 안에 있고 서로가 1순위면 바로 연결
- **좋아요·넘기기**: 서로 좋아요를 누르면 매칭. 프로필 상세에서 **좋아요와 함께 한마디**(60자)를 보낼 수 있어서 매칭 전에도 마음을 전할 수 있음
- **페르소나 추천 카드**: 오늘의 추천을 A·B·C 카드로. 유형 이름(예: "아웃도어 탐험가형"), 한 줄 소개, 궁합 막대(관심사·생활 리듬·가치관 %), #태그, "이래서 추천했어요"
- **매칭 성사 화면**: 서로 좋아요(또는 자동 매칭)가 되면 축하 화면. 공통점, 첫 인사 추천 3개(누르면 입력창에), 대화 시작 / 집중하기 / 계속 둘러보기
- **전국 서비스**: 사는 곳은 17개 시·도 92개 시·군·구 중에서 (가입 화면에서 시·도별로 묶어서 고름, `src/regions.py` 한 곳에서 관리). 시연판 가상 회원 500명도 전국에 퍼져 있고, 수도권은 가까이·광역시는 중간·도 지역은 멀리까지 원하는 거리를 다르게. 등급으로 나눠 추천하는 건 주변에 회원이 40명 이상인 사람끼리만 (지방에서 추천이 비지 않게). 시연판 로그인 화면에 부산·대구·광주·제주 회원도
- **상대 정보는 점수에만**: 직업·키·MBTI·생활 습관·가치관은 궁합 계산에만 쓰고 상대 프로필에 보여주지 않음 ("🔒 대화하면서 직접 알아가 보세요"). 추천 이유도 "술자리 취향이 잘 맞아요"처럼 맞는지만 말하고 값은 숨김. AI 서버 프롬프트도 같은 규칙. 보이는 건 사진·닉네임·나이·동네·거리·자기소개·관심사·등급
- **프로필 등급**: 브론즈·실버·골드·플래티넘·다이아. 외모가 아니라 프로필 관리로만 매기는 100점 (사진 20, 사진 인증 20, 자기소개 길이 20, 관심사 15, 직업·키·MBTI 15, 최근 활동 10). **등급이 2단계 이상 차이 나면 서로 추천하지 않아서** 비슷한 등급끼리 만남 (회원 40명 이상일 때). 내 정보 맨 위에 등급 카드와 "자기소개를 60자 넘게 쓰면 올라가요" 같은 올리는 방법, 카드·상세·성사 화면에 등급 배지
- **매칭 성사 화면**: 상대 사진을 크게(손가락을 따라 3D로 기울고 빛 반사), 궁합 점수가 0부터 올라가고 하트가 터짐, 나머지는 #카페 #둘다아침형 같은 작은 키워드. "대화 시작하기"를 누르면 첫 인사 추천이 입력창에 들어가 있음
- **움직이는 배경**: WebGL 셰이더로 오로라처럼 흐르는 파스텔 빛과 반짝이, 손가락이 닿는 곳에 빛이 따라옴. 해상도 절반·초당 30번·안 보이면 멈춤으로 가볍게, '동작 줄이기' 설정이면 멈춘 한 장
- **취향 핫플 지도**: 매칭되면 성사 화면과 대화방 맨 위에 "두 분 취향 핫플 TOP 3" 버튼. 누르면 지도(OpenStreetMap)에 나·상대·추천 핫플 3곳이 핀으로 뜸. 전국 핫플 56곳(서울·수도권, 부산, 대구, 대전, 광주, 울산, 세종, 강릉, 속초, 춘천, 청주, 천안, 전주, 여수, 순천, 경주, 포항, 창원, 진주, 제주) 중 두 사람 공통 관심사, 두 집 사이 거리, 이동 거리 공평함(한쪽만 멀지 않게), 술·야외 취향으로 골라 "♥ 둘 다 카페를 좋아해서"처럼 이유를 보여줌. **네이버 지도·카카오맵** 버튼은 '성수동 베이커리'처럼 두 사람 취향 검색어로 지도 앱을 열어서 가게 정보는 늘 최신. "이 핫플 제안하기"를 누르면 대화방에 지도 버튼이 달린 제안 카드가 감. 기존 데이트 코스 추천은 이 화면 아래로 옮김
- **매칭 후 다음 매칭**: 동시에 3명까지 대화, 매칭된 사람은 다음 추천부터 빠짐, **집중 모드**(새 추천 쉬고 남의 추천에도 안 나옴), **대화 마치기**(서로 다시 추천 안 됨, 상대에게 정중한 종료 알림)
- **대화 데이터 (`src/dialogues.json`)**: 관심사 44개별 이어 갈 질문, 대화 의도 18가지(인사·주말·직업·사는 곳·음식·술·MBTI·만남 제안·짧은 답 등)와 답장, 상황별 좋은 답장 예시 28개. 시연판 가상 회원은 이 데이터로 '반응 → 답 → 되묻기' 순서로 답하고, **AI 서버가 켜져 있으면 AI가 그 회원(프로필대로)이 되어 답함** (`/api/persona-reply`, 비슷한 예시를 함께 보여 줌). AI 대화 코치도 비슷한 예시를 보고 답장을 추천. 데이터는 이 파일에 예시를 추가하면 바로 좋아짐
- **시연판 시뮬레이션**: 가상 회원에게 좋아요를 보내면 '상대가 본 내 점수'만큼의 확률로 좋아요를 돌려주고, 매칭 뒤 메시지를 보내면 프로필을 바탕으로 자동 답장 (실제 서비스에는 없음)
- **"만약에" 시뮬레이터**: 홈의 "만약에?"(또는 내 정보 → 추천 설정)에서 항목별 비중을 막대로 바꾸면 내 추천 상위 5명이 바로 다시 정렬됨 (▲▼ 순위 변화, 새로 들어온 사람, 빠지는 사람 표시). '상대가 본 나' 점수와 인기 보정은 그대로 두고 '내가 본 상대' 점수만 새로 계산해서 √(곱)으로 합침. 저장 전에는 미리보기만
- **애프터 체크**: "실제로 만났어요"를 체크하면 "또 만나고 싶어요 / 이번엔 여기까지"를 따로 물음 (다음 날 홈·알림으로 다시 알려줌). 답은 상대에게 안 보이고, **두 사람 모두 '또 만나고 싶어요'일 때만** 서로에게 "애프터 성사"를 알려줌. 보안 규칙(`afters`)으로 상대 답은 둘 다 예일 때만 읽히게 막아서, '아직 안 답함'과 '아니요'를 구분할 수 없음. 답은 추천 학습에 마음 표현보다 무겁게 반영 (예 ×1.6, 아니요 ×−1.3)
- **신규 회원 첫 주 노출 보장**: 가입 7일 안 된 회원이 오늘의 추천 3명에 없으면, 조건(R1~R7)을 통과한 신규 회원 중 가장 잘 맞는 1명을 3번째 자리에 넣음. 단 그 자리 원래 점수의 80% 이상일 때만. 카드에 NEW 표시, 개발자 화면에 "원래 n위 → 3번째 자리" 표시 (시연판은 가상 회원 25명 중 1명꼴을 이번 주 가입자로 가정)
- **채팅**: 매칭된 사람과 메시지·사진 주고받기
- **마음 표현**: 만나기 전(좋아요 / 관심 있어요 / 만나보고 싶어요), 만난 뒤(한 번 더 만나볼래요 / 즐거웠어요 / 인연이 아닌 것 같아요)
- **관심사 검색**: "주말엔 산 타요"처럼 문장으로 검색, 검색 공개에 동의한 사람만 노출, 취향 지도로 거리 표시
- **알림**: 좋아요·마음 표현·메시지·자동 매칭·사진 인증 결과를 종 모양 알림함에 모으고, 다른 탭에 있을 때 브라우저 알림
- **데이트 코스 추천**: 매칭되면 채팅 위에 두 사람 중간 지점 근처 데이트 코스(2~3단계, 소요 시간·예산·추천 시간)를 추천. 분위기(취향 맞춤 / 가볍게 / 신나게 / 몸 쓰는 / 감성·문화 / 맛있게 / 아늑하게)를 골라 볼 수 있고, 코스를 골라 제안 메시지로 보냄. 서로 "만나보고 싶어요"(또는 "한 번 더")를 고르면 "약속 잡기 도우미"로 바뀜
  - 코스 점수 = 관심사 겹침(둘 다 1.0, 한 명만 0.3×중요도, 같은 분류 0.1) + 1.2 × 취향 좌표 가까움 + 생활 패턴 보정(술 안 마시는 사람이 있으면 술자리 코스 −1.5, 절약형이면 비싼 코스 −0.4, 둘 다 집순이·집돌이면 야외 −0.3 · 아늑한 코스 +0.3, 둘 다 밖순이면 야외 +0.3)
  - 코스 목록은 `src/app_template.html`의 `COURSES`에서 추가·수정
- **차단·신고**: 프로필·채팅의 ··· 메뉴. 차단하면 서로 추천·검색·채팅에서 사라지고, 신고는 관리자에게만 보임
- **사진 인증**: 그날 정해진 자세로 셀카를 올리면 관리자가 프로필 사진과 비교해 승인 → 인증 배지
- **관리자 화면**: 가입 현황, 신고 처리(이용 정지 / 문제 없음), 사진 인증 승인·반려, 정지 회원 관리, 인기 쏠림 현황
- **이용약관·개인정보 처리방침**: 가입 때 동의 필수, 로그인 화면·내 정보에서 언제든 열람
- **개발자 화면**: 스위치를 켜면 항목별 점수 계산서와 좌표 비교가 보임
- **AI 기능 (LLM)** — AI 서버(`server/`, Claude API 또는 Ollama)가 켜져 있을 때. 자세한 내용은 [docs/AI.md](docs/AI.md)
  - **AI 궁합 분석**: 프로필 상세에서 성향·연애 가치관·대화 스타일·연락 빈도를 비교해 잘 맞는 점, 다른 점, 첫 질문을 자연어로 설명 (순위는 매칭 엔진 점수 그대로)
  - **AI 대화 코치**: 채팅 입력창 옆 AI 버튼 → 말투별 답장 후보 3개, 대화가 끊겼을 때 이어 갈 질문. 고르면 입력창에 들어가고 고쳐서 보냄
  - **첫 만남 대화 주제**: 공통 관심사로 가벼운 질문, 대화 흐름, 피할 질문
  - **AI 자기소개 도우미**: 내 정보에서 키워드·경험을 자연스러운 자기소개 후보 3개로
  - **대화 안전 점검**: 금전 요구·투자 권유·협박 등 위험 표현을 기기 안에서 먼저 알리고, 원하면 AI가 문제점과 대응 방법을 설명 → 신고·차단으로 연결. AI가 단정하거나 자동 제재하지 않음
  - **AI 데이트 플래너**: 예산·날짜·시간대로 중간 지점 근처 실제 장소(카카오/구글)를 엮어 일정, 영업시간, 이동 시간, 길찾기 링크

## 매칭 로직

| 단계 | 내용 |
|---|---|
| 1. 거르기 | R1 프로필 완성 · R2 성별 · R3 나이 · R4 거리(중요도 3이면 탈락, 1·2면 감점) · R5 만남 목적 · R6 절대 조건 · R7 관심사 태그 (양방향) |
| 2. 점수 | 항목별 유사도(0~1) × 가중치, 합계 100점. 가중치는 만남 목적마다 다름 (아래 표) |
| 3. 양방향 | 최종 = √(내가 본 상대 × 상대가 본 나). 내 가중치는 내 쪽 점수에만 쓰임 |
| 3-1. 인기 쏠림 완화 | 다른 회원의 상위 3명에 3번 넘게 든 사람은 넘는 횟수마다 점수 × 1/(1+0.03×초과) |
| 4. 자동 매칭 | 서로의 상위 3명 안에서 서로 1순위인 쌍을 연결, 남은 사람끼리 반복 (차단한 사이는 제외) |

| | 관심사 | 결혼관 | 연락 | 거리 | 외모 | 활동 시간 | 주말 | 음주 | 소비 | 반려동물 |
|---|---|---|---|---|---|---|---|---|---|---|
| 동네친구 | 30 | 0 | 12 | 22 | 0 | 8 | 12 | 6 | 4 | 6 |
| 데이트 | 22 | 8 | 15 | 12 | 14 | 6 | 8 | 7 | 4 | 4 |
| 새로운 시작 | 16 | 22 | 15 | 8 | 8 | 6 | 6 | 6 | 9 | 4 |

**마음 표현으로 학습**: 매칭된 사람에게 마음을 2번 이상 표현하면, 좋게 본 사람(만나보고 싶어요 ×1.0, 한 번 더 ×1.3 …)과 평소 후보보다 더 잘 맞았던 항목은 무게를 올리고, "인연이 아닌 것 같아요"(×−1)였던 사람과 잘 맞았던 항목은 내려요. 배율은 0.6~1.6배 사이로 제한하고, 내 쪽 점수에만 반영돼요.

**관심사 점수** = 0.6 × 태그 겹침 + 0.4 × 취향 좌표 가까움

- 태그 겹침: 같은 태그 1.0 / 관련 태그(등산≈캠핑) 0.5 / 같은 분류(야구↔축구) 0.25, 드문 태그일수록 가중(희귀도), 중요도 ★ ×0.6 · ★★ ×1.0 · ★★★ ×1.6, 겹칠수록 추가 점수는 줄어듦(1 − 0.5^k)
- 취향 좌표: 관심사마다 8개 축(활동성, 야외, 사교, 문화·감성, 미식, 집콕, 몰입·창작, 새로움) 좌표를 두고 코사인 유사도로 비교. 검색도 같은 좌표로 가까운 사람을 찾음

## 핸드폰으로 쓰기 (모바일·홈 화면 앱)

핸드폰에서 주로 쓰는 걸 기준으로 만들었어요.
- **홈 화면 앱(PWA)**: 안드로이드는 화면 아래 "설치" 안내, 아이폰은 Safari 공유 버튼 → "홈 화면에 추가". 주소창 없이 앱처럼 열리고, 인터넷이 끊겨도 마지막 화면은 열림
- **뒤로 가기**: 상세·채팅 같은 시트가 열려 있으면 핸드폰 뒤로 가기로 시트만 닫힘 (앱이 꺼지지 않음)
- **키보드**: 입력칸을 눌러도 화면이 확대되지 않고(글자 16px), 키보드가 올라와도 채팅 입력창·마지막 메시지가 보임. 숫자 칸은 숫자 키패드, 채팅은 "보내기" 키
- **손가락 크기**: 누르는 버튼은 44px 이상, 노치·홈 바 자리 비워 둠, 시트가 열리면 뒤 화면은 고정
- 만드는 기준은 `둘_모바일 웹사이트 프롬프트.txt`

## 두 가지 버전

| | 실제 서비스 (배포판) | 시연판 |
|---|---|---|
| 파일 | `public/index.html` | `src/gyeol_app.html` (빌드해서 생성) |
| 회원 | 가입한 실제 사람만 | 가상 회원 500명 (user001~user500 / 1234) |
| 만들기 | `python3 build_deploy.py ..` | `python3 build_app.py` |

배포판의 개인정보 보호 (Firestore 보안 규칙):
- 가입한 회원만 다른 회원 프로필을 볼 수 있음 (로그인 전에는 아무 데이터도 읽지 않음)
- 프로필은 본인만 만들고 고치고 지울 수 있음, 아이디·비밀번호는 프로필에 저장하지 않음
- 좋아요·마음 표현·차단은 주고받은 두 사람만, 채팅·사진은 대화하는 두 사람만 읽을 수 있음
- 신고·인증 셀카는 관리자만, 매일 추천 기록은 본인만 읽을 수 있음. 관리자도 대화 내용은 못 봄
- 관리자는 Firebase 콘솔에서 `admins/{회원 번호}` 문서를 만든 사람만 (docs/DEPLOY.md 4번)

## 고치고 다시 만들기

```bash

## 가장 쉬운 실행 (Windows)

폴더 맨 위의 **`둘 실행.bat`**을 더블클릭하면 Ollama와 AI 서버를 켜고 브라우저로 http://localhost:8000 을 열어요 (이미 켜져 있으면 바로 열어요).
처음 한 번은 AI 서버용 Python 환경을 만드느라 1~2분 걸려요. 끄려면 **`둘 끄기.bat`**.
컴퓨터를 켤 때 자동으로 켜지게 하려면 `server/autostart_on.bat`을 한 번 실행하세요.

## 수업 시연 (Mac, 노트북 + 학생 핸드폰)

`둘 시연 시작.command`를 더블클릭하면 한 번에 준비돼요.
1. Ollama를 켜고 AI 모델을 미리 올려 둠 (첫 AI 답이 늦지 않게, 2시간 유지)
2. 시연판을 만들고 AI 서버를 켬 → 노트북 브라우저에 http://localhost:8000
3. Cloudflare 임시 터널로 **https 공유 링크**를 만들고 클립보드에 복사, **QR 코드 화면**을 띄움 → 프로젝터에 띄우면 학생들이 카메라로 찍어 바로 접속
4. 시연하는 동안 맥이 잠들지 않게 함
5. 창을 닫거나 Ctrl+C를 누르면 서버·공유 링크가 모두 꺼짐

- 공유 링크는 실행할 때마다 바뀌고, 맥이 켜져 있어야 열려요. AI 답은 한 명씩 차례로 (10~30초)
- AI 사용 한도(10분 40번)는 핸드폰마다 따로 세요 (터널이 알려 주는 실제 접속 주소 기준)
- 필요한 것: Ollama + `ollama pull qwen2.5:7b`, `~/.dul-bin/cloudflared` (Cloudflare 공식 배포 파일)

## AI 기능까지 켜서 실행 (내 컴퓨터)

cd server

```
