너는 매칭 웹앱 "둘(dul)"을 핸드폰에서 주로 쓰는 모바일 웹사이트로 만드는 개발자야.
사용자는 거의 다 핸드폰(아이폰 Safari, 안드로이드 Chrome·삼성 인터넷)으로 들어온다.
PC 화면은 "가운데 놓인 핸드폰 화면"으로만 보여주면 된다.
코드 주석과 화면 문구는 한국어로 쓰고, 구조는 단순하게, 무엇을 왜 바꿨는지 짧게 설명해.

- 슬로건: "좋은 사람과, 더 좋은 날을" / 동네친구 · 데이트 · 새로운 시작

[1] 화면 구성 (모바일 한 손 사용 기준)
==================================================
- 아래 고정 탭바 4개: 추천 / 매칭 / 채팅 / 내 정보 (엄지가 닿는 곳, 아이콘 + 글자, 안 읽은 수 배지)
- 위 고정 바: 로고 "dul" + 알림 종 (스크롤해도 붙어 있음, 반투명 블러)
- 상세·채팅·설정·신고 같은 2단계 화면은 아래에서 올라오는 시트(바텀시트) 또는 전체 화면 시트
- 화면 목록
  1) 로그인·회원가입: 그라데이션 hero + 도시 실루엣, 아이디/비밀번호, 가입 설문(관심사, 생활 패턴, 원하는 상대)
  2) 추천(홈): "오늘도 좋은 인연이 기다리고 있어요 ♥", 관심사 문장 검색, "만약에?" 카드,
     오늘의 추천 3명 카드(사진 꽉 채움, 궁합 등급 태그, ✕ 넘기기 / ♥ 좋아요)
  3) 매칭: 서로 좋아요 / 자동 매칭된 사람 목록, 마음 표현, 애프터 체크
  4) 채팅: 말풍선(상대는 왼쪽 + 프로필 사진, 나는 오른쪽 연핑크), 사진 보내기, AI 도우미, 데이트 코스 추천
  5) 내 정보: 프로필 수정, 자기소개 AI 도우미, 추천 설정(나이·거리·비중), 차단 목록, 탈퇴, 개인정보 처리방침
- 각 화면에 빈 상태(사람 없음, 대화 없음)와 불러오는 중 상태를 꼭 둔다

[2] 모바일 필수 요구사항
==================================================
- 화면 폭: 360~430px를 기준으로 디자인, 최대 520px에서 가운데 정렬. 가로 스크롤 금지
- 뷰포트: width=device-width, initial-scale=1, viewport-fit=cover (확대 막지 않기 — 접근성)
- 노치·홈 바: env(safe-area-inset-*)로 위 바, 아래 탭바, 시트 아래 버튼, 채팅 입력창 여백 확보
- 손가락 크기: 누르는 것은 최소 44×44px (아이콘 버튼, 보내기, 첨부, 작은 버튼, 칩)
- 입력칸 글자 16px 이상 (아이폰은 16px보다 작으면 누를 때 화면을 확대해 버림)
- 키보드
  · 숫자 칸 inputmode="numeric", 검색 enterkeyhint="search", 채팅 enterkeyhint="send"
  · 아이디 autocomplete="username", 비밀번호 current-password / new-password, 자동 고침 끄기
  · 키보드가 올라오면 visualViewport 높이(--vvh)만큼만 시트를 그려서 입력창이 가려지지 않게,
    채팅 중이면 마지막 메시지가 보이도록 아래로 스크롤
- 터치
  · touch-action: manipulation (두 번 탭 확대 대기 없앰), 탭할 때 파란 하이라이트 없앰
  · 시트가 열려 있으면 뒤 화면 스크롤 잠금(body.locked), 시트 안 스크롤은 overscroll-behavior: contain
  · hover에만 의존하는 기능 금지 (핸드폰엔 hover가 없음)
- 뒤로 가기: 안드로이드 뒤로 가기 버튼(그리고 아이폰 가장자리 스와이프)으로 앱을 나가지 않고
  맨 위 시트만 닫기. 시트가 열릴 때 history.pushState, popstate에서 closeTop().
  X 버튼으로 닫으면 쌓아 둔 기록도 history.back()으로 정리. Esc 키도 같은 closeTop()
- 사진: 핸드폰 카메라 사진은 크니까 올리기 전에 캔버스로 줄여서 보내기
  (프로필 360×450으로 잘라 JPEG 0.8, 230KB 넘으면 0.5로 다시), accept="image/*"
- 성능: 첫 화면은 3G에서도 3초 안에. 글꼴은 Pretendard dynamic-subset, 이미지는 lazy, 큰 라이브러리 금지
- 다크 모드: prefers-color-scheme에 맞춰 같은 색 토큰으로, theme-color도 라이트/다크 각각

[7] 추천 카드와 매칭 이후 흐름
==================================================
- 추천 카드 = 페르소나 카드 (리서치 페르소나 시트처럼)
  · 카드 위에 큰 글자 A·B·C(인디고→라벤더 그라데이션) + "아주 잘 맞아요 · 궁합 93점"
  · 흰 둥근 카드: 왼쪽 원형 사진 84px, 오른쪽 한 줄 소개("주말마다 밖에서 / 캠핑·등산을 즐기는")와
    유형 이름 + 닉네임("아웃도어 탐험가형 산책러버", 인디고 굵게). 유형은 관심사가 가장 많이 몰린 분야로
    (운동파 / 아웃도어 탐험가형 / 맛집 탐방형 / 감성 문화인형 / 음악 감성형 / 취미 몰입형 / 다정한 일상형)
  · 점선 아래 궁합 막대 3개: 관심사 / 생활 리듬(연락·활동 시간·주말·음주) / 가치관(결혼관·소비·반려동물),
    값 = 그 묶음 점수 ÷ 그 묶음 비중 (%)
  · #태그 알약: 관심사(겹치는 건 핑크), 아침형/저녁형, 주말엔밖으로/집콕, MBTI
  · 카드 아래 연보라 상자 "이래서 추천했어요" + 근거 3개
  · ✕ 넘기기 / ♥ 좋아요 원형 버튼 (매칭된 사람은 "대화하기")
- 매칭 전 연락: 프로필 상세에서 "좋아요와 함께 한마디"(60자, 선택). 받은 사람의 카드·매칭 탭·알림에 보이고,
  매칭되면 대화방 맨 위에 남음
- 매칭 성사 화면 (서로 좋아요 또는 자동 매칭이 새로 생겼을 때 한 번)
  · 두 사람 사진이 양옆에서 다가오고 가운데 하트가 톡, 색종이가 떨어지는 애니메이션 (동작 줄이기 설정이면 끔)
  · "매칭 성사!" + 어떻게 연결됐는지 + 상대의 한마디 + 공통점 태그
  · 첫 인사 추천 3개 (누르면 대화방 입력창에 들어감, 자동 전송 금지)
  · [대화 시작하기] [이 사람에게 집중하기] [계속 둘러보기], 접힌 "다음 매칭은 어떻게 되나요?"
- 매칭 후 다음 매칭 규칙
  · 동시에 대화하는 매칭은 3명까지. 꽉 차면 새 좋아요는 막고 "한 명과 대화를 마치면" 안내
  · 매칭된 사람은 다음 추천부터 빠지고, 빈자리는 다음 날 새로운 사람으로
  · 집중 모드: 한 사람과 알아가는 동안 새 추천을 쉬고, 다른 사람 추천에도 안 나옴 (프로필에는 상대 번호 대신 짝의 해시만)
  · 대화 마치기: 확인 후 대화방이 닫히고 서로 다시 추천 안 됨, 상대에게는 "대화를 마쳤어요" 알림만.
    내 정보에서 "다시 추천 받기"로 되돌릴 수 있음 (차단 목록과 따로 보여줌)
  · 애프터 체크와 마음 표현은 다음 추천 순서에 반영
- 시연판 시뮬레이션 (실제 서비스에는 없음)
  · 가상 회원에게 좋아요 → 1.4~2.8초 "프로필을 보고 있어요…" → '상대가 본 내 점수'가 높을수록 좋아요를 돌려줌
    (70점이면 92%, 45점이면 44%, 최소 35%, 같은 두 사람이면 결과가 늘 같게) + 짧은 한마디
  · 매칭 후 메시지를 보내면 "입력 중" 점 3개 → 프로필(관심사·주말·직업·지역·활동 시간)을 바탕으로 답장,
    대화가 4번 넘게 오가면 먼저 커피 약속을 제안

[8] 취향 핫플 지도 (매칭 후)
==================================================
- 입구: 매칭 성사 화면과 대화방 맨 위의 그라데이션 버튼 하나 "📍 두 분 취향 핫플 TOP 3 / 🌿 연남동 · 🚲 망원 · 📚 서촌"
  (대화방 위에는 이 버튼과 마음 표현만. 기존 데이트 코스 추천은 핫플 화면 아래로 옮겨 화면을 덜 복잡하게)
- 핫플 화면 (전체 화면 시트)
  · 위: 지도 300px (Leaflet + OpenStreetMap, 화면 열 때만 불러옴, 바탕 지도는 채도를 낮춰 핀이 잘 보이게)
    나(인디고)·상대(핑크) 원형 핀, 두 집을 잇는 점선, 추천 핫플은 그림 + 번호 핀, 고른 핀은 크게
  · 아래: 핫플 카드 3개. 그림 타일 + 번호, 이름, 한 줄 소개, "♥ 둘 다 카페를 좋아해서", "나 7km · 상대 5km · 거리 공평"
    고른 카드에만 [네이버 지도](초록) [카카오맵](노랑) [이 핫플 제안하기] 버튼 → 한 번에 하나만 크게
  · "다른 핫플 보기 (1/n)", 맨 아래 데이트 코스 추천
- 핫플 데이터: 서울·수도권 27곳 (성수, 서울숲, 연남, 홍대, 망원, 을지로, 익선, 서촌, 삼청, 대학로, 한남, 용리단길,
  여의도 한강, 더현대, 석촌호수, 잠실야구장, 뚝섬, 가로수길, 강남역, 북한산 우이동, 문래, 광장시장, 건대, 일산 호수공원,
  정자동, 수원 행궁동, 송도). 각 곳에 좌표, 그림, 관심사 태그, 한 줄 소개, 야외·술 여부
- 고르는 법: 잘 맞는 태그 2개(둘 다 좋아함 1.2, 한 명만 0.35×좋아하는 정도) − 0.08×평균 거리(km) − 0.05×거리 차이,
  술 안 마시는 사람이 있으면 술집 거리 −1.5, 둘 다 집콕이면 야외 −0.2. 평균 20km 넘는 곳은 가까운 곳이 6곳 이상이면 뺌
- 지도 앱 연결: 가게 이름을 앱에 넣지 않고 '동네 + 취향 검색어'(예: 성수동 베이커리, 을지로 수제맥주)로
  https://map.naver.com/p/search/… , https://map.kakao.com/link/search/… 를 열어 최신 가게 정보를 보게 함 (키 필요 없음)
- 제안: 대화방에 "🌿 연남동 경의선숲길 어때요?" 카드 말풍선 + 네이버 지도·카카오맵 버튼. 시연판 가상 회원은 "좋아요! 평일 저녁 어떠세요?"로 답함
- 뒤로 가기·Esc로 핫플 화면만 닫히고 대화방으로 돌아감

[9] 프로필 등급, 매칭 성사 화면, 움직이는 배경

- 프로필 등급 (외모가 아니라 프로필 관리로만, 100점)
  · 사진 20, 사진 인증 20, 자기소개 20(60자↑ 20 / 30자↑ 14 / 15자↑ 8 / 조금 4), 관심사 15(5개 10 + ★ 5),
    직업·키·MBTI 각 5, 최근 활동 10(3일 안 10 / 7일 안 6) — 배포판은 접속할 때 seenAt 기록(12시간에 한 번)
  · 브론즈 0 / 실버 50 / 골드 65 / 플래티넘 80 / 다이아 90. 등급마다 색(동·은·금·청록·보라) 알약 배지
  · 비슷한 등급끼리: 등급 차이가 2 이상이면 서로 추천·자동 매칭에서 뺌 (회원 40명 이상일 때만, 적으면 추천이 비어서)
  · 내 정보 맨 위 등급 카드: 점수, 등급 막대, "플래티넘까지 4점", 항목별 점수와 올리는 방법, "외모로 매기지 않아요" 안내
  · 시연판 가상 회원의 사진 인증·접속 기록은 번호로 정해 둠 (35%가 인증)
- 매칭 성사 화면
  · 어두운 보라 배경 위 필기체 "It's a Match ♥", 상대 사진 4:5 크게 (흰 테두리 + 핑크 빛), 아래에 이름·나이·동네·등급
  · 사진은 손가락을 따라 3D로 기울고 빛이 반사됨, 처음 뜰 때 사진이 돌며 등장 + 빛이 한 번 지나감
  · 궁합 점수 68px, 0부터 올라감 / 하트·반짝이 70개가 사진에서 터짐 (#app 밖 캔버스라 화면을 다시 그려도 안 끊김)
  · 나머지는 작은 키워드 6개(#같이 좋아하는 관심사 먼저, #둘다아침형 #결혼관일치 #3km거리 #유형이름)와 상대 한마디 한 줄
  · [대화 시작하기](첫 인사 추천을 입력창에 넣어 둠) / [📍 취향 핫플] [나중에] / 접힌 "다음 매칭은?"
  · 동작 줄이기 설정이면 애니메이션 없이
- 움직이는 배경 (게임 엔진 대신 WebGL 셰이더 하나)
  · 유니티 WebGL은 수십 MB에 핸드폰에서 느리고 배터리를 많이 써서 웹앱 배경으로는 맞지 않음 → 셰이더 몇 KB로 같은 느낌
  · 노이즈를 겹친 오로라 그라데이션(라이트: 라벤더·연핑크·인디고 / 다크: 남색·자주·보라) + 반짝이 + 손가락 위치에 빛
  · 화면 해상도 절반, 초당 30번, 탭이 안 보이면 멈춤, 동작 줄이기면 한 장. WebGL이 없으면 원래 CSS 그라데이션
  · 앱 바탕(#app)을 반투명으로 해서 배경이 비치게, 카드는 그대로 불투명이라 글씨는 잘 읽힘
